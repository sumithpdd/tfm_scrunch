# AGENTS.md

Guidance for AI coding agents working in this repository.

## Project

**TFM Scrunch** — a small public-facing Next.js microsite built for the Sitecore + Scrunch stand
at Technology for Marketing 2026 (technologyformarketing.co.uk). Visitors enter their name,
company, email, and website, and get a free, light-touch **AEO/GEO discoverability audit**
generated by Gemini. A second page, **AI Marketing Skills**, showcases a read-only prompt library.

Forked from the `/scrunch` (internal brand-setup wizard) and `/ai-marketing-skills` routes of the
`SitecoreAiDemoSenario` repo — same stack, conventions, and code style, but trimmed to a public,
auth-free, two-page booth tool. No visitor login, no multi-brand CMS. Firebase Admin is used
server-only to persist booth leads in `tmf_scrunch_leads`.

## Audience

Booth visitors at Technology for Marketing 2026, running the audit themselves on a kiosk or their
own device. Secondary audience: Sitecore/Scrunch sellers reusing the prompt library.

## Before you change code

1. Read `.cursor/rules/project.mdc` and `.cursor/rules/security.mdc`
2. Branding (company, presenter, CTA copy, event name) lives in one place: `src/lib/site-config.ts`
   — change it there, not by hunting through components.
3. Never commit secrets or real keys to docs.

## Common tasks

- **Change branding / CTA / contact info**: edit `src/lib/site-config.ts` only.
- **Add/edit a marketing skill**: edit `src/lib/marketing-skills-seed.ts` (ships in code — no
  admin UI).
- **Tune the audit's tone/scope**: edit `AUDIT_SYSTEM_PROMPT` in
  `src/server/audit/prompts/audit-brief.ts`.
- **Export leads captured at the booth**: open the hidden `/stand-desk` page (passcode =
  `LEADS_ADMIN_SECRET`), or the Firestore collection `tmf_scrunch_leads`. `data/leads.jsonl` is a
  local fallback.
- **Email the visitor a PDF**: set `RESEND_API_KEY` and a verified `EMAIL_FROM` (see `.env.example`).
  Download PDF works without those; Send me an email then falls back to a mail-app draft + PDF download.
- **Deploy**: set `GEMINI_API_KEY`, `FIREBASE_SERVICE_ACCOUNT_JSON`,
  `NEXT_PUBLIC_FIREBASE_PROJECT_ID`, and `LEADS_ADMIN_SECRET` (and optionally `GEMINI_MODEL`,
  `NEXT_PUBLIC_SITE_URL`, `RESEND_API_KEY`, `EMAIL_FROM`) on Vercel. See `.env.example`.

## Do not

- Put API keys, Gemini keys, or Scrunch org/brand ids in markdown, UI placeholders, or committed
  env files.
- Call Gemini from client components (server routes / server-only modules only).
- Add a login/auth layer on the visitor kiosk without also adding a reason — booth visitors should
  never see a sign-in screen. The `/stand-desk` passcode is staff-only and must stay off the nav.
- Claim the audit is a live Scrunch/AI-assistant check. It is Gemini research and hypothesis
  generation — say so in the UI and prompt (`AUDIT_SYSTEM_PROMPT` enforces this; keep it that way).
